# 实施流程

本文说明本项目从原始数据到公开译稿的完整流程：每一步做什么、由谁来做、用什么工具，以及有哪些检查。翻译时的具体体例另见 [翻译规范](翻译规范.md)，译名见 [译名规范](译名规范.md)。

> 本项目的目录、拟译书名、注释关系和全部译稿，都由 AI 在脚本和规则辅助下生成，**尚未经过人工审定**。本文所说的“审核”都是 AI 交叉审核，不能代替专家审定。

---

## 一、项目目标与范围

- **整理**：把藏文大藏经三部分合并成一个总目录，共 6,388 条：甘珠尔（佛语部）1,138 条，丹珠尔（论疏部）3,406 条，松绷（藏地祖师文集）1,844 条。同时整理版本对照表、经—论—注疏的注释关系，并核对哪些典籍已有汉译。
- **翻译**：把没有汉译的藏文论典译成藏汉逐段对照的研究译稿。
- **原则**：
  - 不重复别人已经完成的工作。已有完整、可靠的现代汉译，就不重译。
  - 不译密续，原因是宗派传承与灌顶要求。
  - 不使用受著作权保护的内容，也不分发这类内容。
  - 按大类推进：唯识 → 中观 → 道次第 → ……，一类做完再做下一类。

## 二、目录结构

本项目分成两层：

| 位置 | 内容 | 是否公开 |
|---|---|---|
| 仓库根目录（`catalog/`、`site/`、`scripts/`、`translations/`、`docs/`） | 公开的目录、检索网页、脚本、译稿、文档 | 推送到 GitHub |
| `_本地数据/`（git 已忽略） | 藏文全文、下载来源包、所有工作稿与中间文件 | **只在本地，绝不提交** |

`_本地数据/` 中的主要内容：

| 子目录 | 内容 |
|---|---|
| `甘珠尔最全版/`、`丹珠尔最全版/`、`松绷最全版/` | 合并后的藏文全文：`1_校正版_dhammareader/` 是主底本，`4_德格版_Esukhia/` 是对校本 |
| `_来源/` | 原始下载数据：dhammareader、ACIP 官方包、Esukhia、rKTs |
| `_工具/` | 编目、发布、自检、审核队列等脚本 |
| `翻译/` | **译稿的工作版（唯一原稿）**，按批次分子目录；每部或每段另有 `_work_*` 工作目录 |
| `翻译/现代汉译排除/` | 汉译核查资料：已知译者目录、核查记录、核查总表 |
| `翻译/审核说明/` | 三份审核任务说明 |
| `翻译/模型测评/` | 选择翻译与审核模型时的测评材料和报告 |
| `发布文件/word/`、`发布文件/pdf/` | 给读者下载的 Word / PDF 成品（由公开版译稿自动生成，上传到 GitHub Release）；`manifest.json` 记录每部的内容指纹 |

仓库中与成品相关的公开脚本在 `scripts/docx/`：`md2docx.py`（生成 Word）、`md2pdf_chrome.py`（生成 PDF）。

**工作版与公开版**：`translations/` 是由发布脚本从 `_本地数据/翻译/` 导出的公开副本，导出时会去掉本机路径、参照译文等内容，并通过自检。**所有修改都只改工作版**，然后重新发布；直接改公开版的内容，会在下次发布时被覆盖。

## 四、阶段一：数据准备与编目（已完成）

1. **收集来源**：
   - ACIP 本地 2016 版、ACIP 官方 2026 包、dhammareader 校正版：都是公有领域，dhammareader 为 CC BY 4.0；
   - Esukhia 德格版：公有领域；
   - rKTs 编号对照：CC0。
2. **三方合并**：先做规范化（去掉标点变体，统一梵文叠字写法），再用 4-gram 比对去重，合并成“最全版”。同时修正 pyewts 的梵文叠字转写错误。
3. **编目**：
   - 各部汉文目录，含拟译书名、译名类型、作者、各版本编号；
   - 由 `scripts/canon/build_master_catalog.py` 合成总目录，再由 `build_site_data.py` 生成检索网页的数据。
4. **汉译核对**：对照大正藏和 CBETA 补编、大慈恩月光藏等书目，标出哪些典籍已有汉译。
5. **注释关系**：先用规则生成候选，再逐条确认，得到 1,044 条经—论—注疏关系，并生成注疏谱系。

## 五、阶段二：选书

### 1. 按大类与价值排序
在当前大类中，优先选择：
- 注释玄奘等古译根本论的印度注疏；
- 古译不全或质量存疑的论典；
- 篇幅适中、底本完好（有德格本可对校、不缺页）的论典。

### 2. 三道核查（必做，全部通过才能开译）
1. **对照已知译者目录**：
   - 韩镜清（1912–2003）译著目录：他几乎译遍了丹珠尔唯识部的核心注疏，书名常与通行书名不同，**要按作者加篇幅来比定**；
   - 钦哲基金会“圆满法藏”的待译目录（标“翻译中”“译注已完成”）和站内搜索；
   - CBETA 补编、大慈恩月光藏。
2. **Codex 联网核查**：书名、作者的各种异名、学位论文、期刊都要查。
3. **Claude 独立检索**：结果与 Codex 一致才算通过。

**判定规则**：
- 已有完整、可靠的现代汉译：不译；
- 原译只译了一部分：只补译缺的部分，并在解题中说明已有译本的出处。

**已知陷阱**：
- 圆满法藏目录的备注**不收韩镜清的手稿**，不能凭“没有备注”就排除韩镜清译本。
- 现代译者（法尊等）在其他书中的转引片段，不算独立译本；但这些片段不能采用，也不能抄录。

核查结果汇总在 [汉译核查总表_唯识部](汉译核查总表_唯识部.md)，本地底稿在 `_本地数据/翻译/现代汉译排除/`。

## 六、阶段三：开译准备

1. **底本与对校本**：主底本用 dhammareader 校正版（`1_校正版_dhammareader/TD<德格号>.txt`），对校本用 Esukhia 德格版（`4_德格版_Esukhia/D<德格号>.txt`）。
2. **切段**：超过约 2 万音节的论典，按卷（藏文 བམ་པོ）切成每段 1–2 万音节，每段的底本单独存一份。
3. **共同说明**：分段翻译时，写一份所有译者共用的说明，统一体例、术语、段号格式和引经处理方式。
4. **参照资料**：
   - 所释论典的古译：本机 CBETA；
   - 疏：凡是有疏的，疑难处必须查阅；
   - 藏译本论：比如注释《菩萨地》的书，要对照藏译《菩萨地》。

## 七、阶段四：翻译（Claude 子代理）

每个译者先读翻译规范，要点如下：

- **全文翻译，不删节**。读不通的地方也要照字面暂译，可以加问号；**不能用省略号或保留藏文代替译文**，疑问写进校注。
- **藏汉逐段对照**：每段先列藏文，后列汉译；段落编号用〔n〕，分段翻译时用〔段号-n〕。
- **两本对校**：逐音节比对，列出异文表；按德格本改读的地方要出校注。
- **底本疑有讹误**：出校注，不能悄悄改；**校注中已判断出的正读，必须同步到正文**。
- **专有名词**：拿不准的照字面译，比定只写在校注里；绝不补出原文没有的人名、书名。
- **引文**：
  - 古代译本（玄奘等）可以采用，标出 CBETA 页栏行；
  - 现代译者的译文（CBETA B 编、G 编等）不采用，只标出处；
  - 出处查不到的，标“出处待考”，不能凭记忆编造。
- **藏文核对**：用脚本把译稿中的藏文拼回去，必须与底本逐字一致；还要做反向测试（故意改坏一个字，脚本必须报错）。
- **文末自查**：列出最没把握的 10 处，并写明这次检查看不见什么。
- **硬性约束**：不得再派下级子代理；只能使用分配给自己的工作目录；篇幅长的，每完成一部分就追加写入。

## 八、阶段五：审核

| 层级 | 执行者 | 范围 | 说明文件 |
|---|---|---|---|
| 1. 整部审核 | 全新的 Claude 子代理 | 整部 | `翻译/审核说明/Claude审核说明.md` |
| 2. 重点复核 | Codex | 自查里最没把握的 10 处、Claude 列出的“需要第二意见”处、没有汉文参照的段落 | `翻译/审核说明/Codex重点复核说明.md` |
| 3. 抽样整部审核 | Codex | 每 3–5 部抽 1 部 | `翻译/审核说明/Codex整部审核说明.md` |

- **Claude 审核员的硬性要求**：凡是能用依据核实的，都要核实，并注明依据位置。依据包括藏译本论、疏、古译和对校本。没有依据的判断，把握最高只能标“中”。
- **Codex 调用方式**：`ask codex -s read-only -C <工作目录> "……"`，让 Codex 自己读取文件。大文件不能用 `-f` 传入，会报 “Argument list too long”。
- **审核意见的处理**：交给**原译者**逐条判断，采纳的改正，不采纳或部分采纳的写明理由。审核记录以表格附在译稿末尾，写明审核员、日期和每条的处理结果。处理完后，必须重跑藏文核对。
- **主会话抽查**：抽查关键改动，并确认正文中已没有省略号和未译的藏文。

> 2026-11-19 以前的译稿都是 Codex 整部审核。新的分工以《菩萨戒品广释》（T-2955）上 Claude 审核与 Codex 审核的对比结果为准：Claude 能检出 Codex 高把握问题的 70% 以上，就照此执行；低于 50%，就退回以 Codex 为主。

## 九、阶段六：统稿（分段翻译的论典）

1. **合并脚本**：以 `翻译/释轨论/_合并/merge.py` 为模板，依次完成：
   - 拼接各段的正文和附录；
   - 全书统一段号为〔段.序号〕；
   - 段间互相引用的段号一并替换；
   - 把各段附录标题标上段号（例如“第 2 段·校注”）。
2. **合并后的验证（脚本自动完成）**：
   - 每段正文的藏文与该段底本逐字一致。叶码有 `[29A]` 和 `【29A】` 两种写法，比对时要先统一；
   - 各段底本首尾相接，等于全书底本；
   - 不残留旧格式的段号。
3. **全书前言**：由一个子代理撰写，只读各段的解题、译例、术语表和自查，不读正文。内容包括：
   - 文件头和各段对照表；
   - 全书解题，并撤回各段解题中证据不足的断言；
   - 全书译例；
   - 统一术语表，列出各段译法不一的地方和推荐译名；
   - 全书最需复核的地方。

## 十、阶段七：发布

1. 把编号加入 `_本地数据/翻译/已复核.txt`。只有列在这里的译稿才会被导出。
2. 运行：

   ```bash
   bash _本地数据/_工具/发布.sh "提交说明"
   ```

   脚本会依次：同步目录与网页数据 → 导出译稿到 `translations/` → 运行 `precheck_public.py` 自检 → 自检通过才提交并推送。
3. **自检内容**：
   - 不含本机路径和个人信息；
   - 与参照译文没有 10 字以上的重合片段；
   - 引文出处标注里没有采用 B 编、G 编的现代译文；
   - 没有藏文全文文件；
   - 没有超大文件。

   自检只扫描 git 会提交的文件，不扫描 `_本地数据/`。
4. **提交规范**：使用 noreply 邮箱，不加 AI 署名。
5. **读者成品（Word / PDF）**：发布脚本推送后自动执行：
   - `_工具/make_release_files.py` **增量**生成（按内容 sha256 判断，没改的跳过）：
     - Word 由 `scripts/docx/md2docx.py` 生成：汉字宋体，藏文按复杂文字设为 Microsoft Himalaya；生成后逐字核对藏文。
     - PDF 由 `scripts/docx/md2pdf_chrome.py` 生成：Markdown → HTML → Chrome 无界面打印，字体嵌入，按标题生成书签；《释轨论》411 页约 4 秒。
     - 2026-11-19 对比测试中，Chrome 版排版优于 Windows Word 导出版；后者 443 页要 8 分钟，作为备用方案保留（`_工具/docx2pdf_word.sh`）。
   - `_工具/release_sync.sh` 同步到 GitHub Release 的 `translations` 版本：附件文件名用编号，显示名用“编号 书名（格式）”；已撤下的译稿，其旧附件会被删除。
   - 成品本地存放在 `_本地数据/发布文件/{word,pdf}/<编号>_<书名>_<日期>`，不进 git。

## 十一、额度与并发管理

| 资源 | 实测 | 做法 |
|---|---|---|
| Claude 5 小时额度 | 约 10 个 Opus 子代理并行时，约 30 分钟用掉约 40% | 平时最多同时 2 个翻译子代理；周额度临近重置时可以放开 |
| Claude 周额度 | 一个完整的 5 小时窗口约合周额度的 13%（推算） | 周额度用不完时，主要卡在 5 小时上限 |
| Codex 5 小时额度 | 约够审 11 份大稿 | 用审核队列串行执行 |
| Codex 周额度 | 一次整部审核约用 2% | 以重点复核为主，整部审核只抽样 |

- **额度用尽时**：子代理会暂停，进度保存在工作目录里。额度恢复后，给**原子代理**发消息，让它接着做；不要重开新的子代理。
- **Codex 审核队列**：`bash _本地数据/_工具/codex_queue.sh _本地数据/翻译/codex_队列.txt`。队列逐条串行执行，已经审过的自动跳过；遇到额度用尽，会从 Codex 日志里读出恢复时间，到时自动接着审。

## 十二、质量检查一览，以及每项检查看不见什么

| 检查 | 能保证 | 看不见 |
|---|---|---|
| 藏文逐字核对 | 藏文没有漏抄、错抄 | 译文对不对 |
| 两本对校 | 录入差异与部分讹误 | 两本都出自德格版，共同的错误对校不出来 |
| 古译对勘、CBETA 页栏核对 | 引文出处真实 | 作者自己的论述部分没有汉文参照 |
| Claude 整部审核 | 有依据可以核实的错误 | 与译者同一个模型，没有依据的段落可能一起看漏 |
| Codex 复核 | 另一家模型的独立判断 | 只看抽到的位置 |
| 公开前自检 | 隐私、版权、文件规模 | 译文质量 |

## 十三、已知问题与教训

| 问题 | 教训 / 现行做法 |
|---|---|
| 开译后才发现韩镜清已有译本，停掉了 8 个子代理 | 三道核查全部通过才能开译；韩镜清的书名要按作者加篇幅比定 |
| 圆满法藏目录的备注不收韩镜清手稿 | 不能用它来排除韩镜清译本 |
| 子代理会自己再派下级子代理，停掉上级时，下级不会一起停 | 任务说明里写明“不得再派子代理” |
| 译者用省略号或保留藏文代替译文 | 规范明令禁止；审核时专门检查 |
| 校注中已判断出正读，正文却没跟着改 | 规范要求同步；审核员专门检查 |
| 疑难处不查疏，把能解的地方当作不可解 | 有疏的论典，疑难处必须查疏 |
| dhammareader 底本有错简、缺叶 | 对校时注意叶码和文意的连续性（如 D4069 叶 275B–276B） |
| 大文件传给 Codex 失败 | 用 `-C 目录` 让 Codex 自己读文件 |
| 后台等待脚本用 pgrep 匹配到了自己 | 改用审核队列脚本 |
| 《般若波罗蜜多教授》（D4079）译完才发现极可能就是韩镜清的《慧度教授论》（1992） | 起因是把韩镜清目录中的这一条比定到了同作者的另一部短论上。比定时书名要拆成梵文对应词（慧度＝般若波罗蜜多，教授＝upadeśa），并用篇幅比例核对 |
| Codex 额度用尽时，审核队列没能自动等待 | 额度提示写在 Codex 日志里，不在错误输出里；队列脚本已改成从日志中读取恢复时间 |
